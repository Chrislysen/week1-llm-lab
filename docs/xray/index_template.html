Zombie Constraint X-ray

Two colleagues plan an incident recovery. One proposes a step; the other explicitly rejects it, and nobody brings it back. Six small local models then write the plan with the whole conversation in front of them. How often does the rejected step come back from the dead?

Within one family the effect falls with scale (qwen2.5 3B → 7B → 14B), which replicates arXiv:2608.12599 with length controlled. Across families it does not: the smallest model here, gemma4:e4b, has the lowest relapse of the six. Both findings are replications and bounds of published work, not novelty claims.

Full raw context
the arm measured above		 Proposal and rejection both stay in the window, adjacent. The restatement is one more line; the rejection is still present. The decider resolves the conflict itself while writing the plan. measured, 6 models
Write-time delete
Mem0 paper pipeline, arXiv:2504.19413 · DEFAULT_UPDATE_MEMORY_PROMPT		 An LLM compares the new fact with retrieved memories and may DELETE the proposal. The delete is hard: no tombstone, and the update prompt is only ever shown live memories. Nothing in the store contradicts it any more, so the restatement is ADDed as a fresh fact. The decider sees only what survived; the rejection itself was never a stored fact. semantics traced · not run
Add-only, no recency ranking
Mem0 OSS v3, April 2026 · ADDITIVE_EXTRACTION_PROMPT		 No UPDATE or DELETE exists. Proposal and rejection both become memories, if the extractor emits them at all. Agent utterances are stored "with equal weight". One more copy of the stale step, retrieved by similarity alone; attributed_to is stored but unused in ranking and temporal features raise an error in OSS. The decider gets the top-k by similarity and must resolve the conflict from copies. semantics traced · not run
Merge-in-place page
Karpathy LLM-wiki pattern, nashsu/llm_wiki · src/lib/ingest.ts		 The step's page is merged "old + new instead of clobbering". Contradictions are not written into the page; they become review items for a human. Merged into the same page. With no human reviewing, the contradiction stays queued and both versions coexist. The decider reads a page that holds the proposal and its rejection side by side. semantics traced · not run

E29, measured. The same 96 dialogues, each rendered twice: once with the original proposer restating the rejected step late in the conversation, once with a length-matched neutral line in the same slot. Each version was delivered to the decider through the four designs above, with every store built from the scorer's own tags so it is the design's semantic ideal. The estimate is the difference-in-differences: how much more the restatement raises relapse under a design than it does under full context.

The restatement effect, by design, decider and corpus

Each mark is Δ = P(rejected step in plan | restated) − P(… | neutral) for one design on one decider, with its paired-bootstrap 95% interval over dialogues. The grey band is the ±0.15 band the read rule uses; the distance of a design's mark from its row's full-context mark is that design's DiD.

      The question E29 asks. Does a partner's later restatement of a rejected step raise the relapse rate by an amount that depends on the memory design, measured as a difference-in-differences against the full-context arm above? The rows above will be filled in with measured rates only after the declared protocol has run.
